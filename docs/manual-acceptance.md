# Manual acceptance checklist

The automated suite (`pytest`, 230 tests) covers everything that can be proven
without a human and a real browser. This document covers the remainder: the
checks that need a person, a real Chrome/Edge profile, and a real download.

Nothing here has been marked as passing on your behalf. Each item states what
was verified automatically, and what still needs you to confirm it.

## What still needs a human

These cannot be automated here because they require installing an unpacked
extension into a real browser profile and completing a real download.

### 1. Install the extension

- [ ] Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge).
- [ ] Turn on **Developer mode**.
- [ ] Choose **Load unpacked** and select the `browser_extension` folder.
- [ ] Copy the 32-character extension ID that the browser assigns.

The ID is generated by the browser from the folder path, so it differs on every
machine. This is why the ID must be pasted into SmartSort rather than being
built in.

### 2. Register the native host

- [ ] In SmartSort, open **About & diagnostics**.
- [ ] Paste the extension ID into the **Extension ID** field.
- [ ] Click **Install browser integration**.
- [ ] Confirm both Chrome and Edge show **Registered**.

This writes only `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.smartsort.host`
and the Edge equivalent. No machine-wide keys, no elevation.

### 3. Confirm the connection

- [ ] Click the SmartSort toolbar icon.
- [ ] The popup should show **Connected** and your destination folder.
- [ ] Click **Test connection**; it should report success.

If the popup reports `host_not_installed`, the registry entry is missing — repeat
step 2. If it reports `extension_not_allowed`, the ID pasted in step 2 does not
match the one the browser shows.

### 4. Organize a real download

- [ ] Set the destination to a **different drive** from your Downloads folder, so
      the cross-volume path is exercised.
- [ ] Enable **Organize completed downloads automatically**.
- [ ] Download a small file (a PDF or a JPG is fine).
- [ ] The file should appear in `<destination>\<YYYY-MM-DD>\Documents\` (or
      `Images\`), and **not** remain in Downloads.
- [ ] The Dashboard's **Recent activity** should list it as **Organized**.

### 5. Prove in-progress files are never touched

- [ ] Start a large download (a few hundred MB) so it runs for a while.
- [ ] While it is still downloading, check the destination folder: it must be
      empty, and the `.crdownload` / `.partial` file must still be in Downloads.
- [ ] Let it finish. Only then should it move.

### 6. Prove nothing is overwritten

- [ ] Download the same file twice, or place a file with the same name in the
      destination folder first.
- [ ] The second copy must be saved as `name (1).ext`, never replacing the first.

### 7. Prove undo

- [ ] In **History**, select an organized row and click **Undo move**.
- [ ] The file returns to its original Downloads location.
- [ ] The row's status changes to **Undone**.
- [ ] Delete the organized file manually, then try undo again: it must refuse and
      explain why, without deleting anything.

### 8. Prove history survives a restart

- [ ] Quit SmartSort from the tray menu, then start it again.
- [ ] The same history rows are still listed.

### 9. Prove failures keep the source file

- [ ] Point the destination at a folder you cannot write to (or remove the drive).
- [ ] Download a file.
- [ ] The operation should be recorded as **Failed**, and the file must still be
      in Downloads.

### 10. Tray and startup behaviour

- [ ] Closing the window minimizes to the tray rather than quitting.
- [ ] The tray menu offers Show / Pause / Quit.
- [ ] **Start with Windows** adds exactly one `HKCU\...\Run` value named
      `SmartSort`, and turning it off removes only that value.

### 11. Remove the integration cleanly

- [ ] Click **Remove browser integration**.
- [ ] Both browsers should show **Not registered**.
- [ ] Confirm no `com.smartsort.host` keys remain under HKCU.

## Fallback path (no extension)

If you would rather not install the extension, turn on **Watch a folder for
finished downloads** in Settings. The watcher polls the folder, waits until a
file's size stops changing for the configured number of seconds, ignores
`.crdownload` / `.part` / `.tmp` files, and then organizes it.

This mode is covered by `tests/unit/test_monitor.py`, but it is inherently a
best-effort heuristic: a download that stalls for longer than the settle window
could be moved while it is still incomplete. The extension path does not have
this weakness because it uses the browser's own completion event.
